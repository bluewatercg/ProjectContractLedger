# 订阅台账提醒与续费归档设计

## 背景

订阅台账模块用于管理周期性续费事项，例如企业微信认证、云服务、域名、软件订阅等。模块需要同时解决两类问题：

1. 提醒用户某个事项什么时候需要处理续费。
2. 归档每次实际续费对应的合同、发票、备注等资料。

提醒计划和续费附件不是同一件事。提醒计划描述“什么时候提醒处理”；附件归档描述“某一次续费实际发生后留存了哪些资料”。

## 目标

- 事项、提醒周期、续费历史三层分离。
- 允许用户同时维护当前到期日和下次提醒开始日。
- 允许保存逾期事项，不在保存时自动顺延。
- 只有用户确认续费时，系统才自动顺延下一轮到期日和提醒开始日。
- 合同、发票只绑定到某次续费历史，不和提醒计划绑定。
- 同一次续费历史下允许多份合同、多份发票。
- 续费历史展开行统一管理附件，支持上传、查看、下载、删除。

## 非目标

- 不做复杂的多提醒规则，例如同一事项多个独立提醒计划。
- 不做合同、发票的结构化识别或 OCR。
- 不要求每次续费必须上传合同或发票。
- 不限制同一次续费只能有一份合同或一份发票。

## 业务模型

### 订阅事项

订阅事项描述“这个事项是什么”。主要字段包括：

- 事项名称
- 事项类型
- 所属主体
- 服务商
- 主负责人
- 其他负责人
- 费用
- 续费方式
- 备注
- 启用状态

### 当前提醒周期

当前提醒周期描述“当前这一轮什么时候到期、什么时候开始提醒”。主要字段包括：

- `current_expiry_date`：当前到期日
- `next_reminder_start_date`：下次提醒开始日
- `renewal_period_value`：周期数值
- `renewal_period_unit`：周期单位，支持日、月、年
- `remind_days_before`：提前提醒天数
- `reminder_mode`：提醒方式，支持每日提醒、只提醒一次

用户可以同时维护当前到期日和下次提醒开始日。若用户未填写下次提醒开始日，系统默认按以下规则生成：

```text
next_reminder_start_date = current_expiry_date - remind_days_before
```

若用户手工填写了下次提醒开始日，系统尊重用户手工值。

允许保存过去或今天的到期日。系统不在保存时自动顺延；状态会显示为临期或逾期，并持续提醒，直到用户确认续费或停用该事项。

### 续费历史

续费历史描述“某一次实际续费”。主要字段包括：

- 操作时间
- 续费前到期日
- 续费后到期日
- 续费周期
- 操作人
- 备注
- 附件列表

合同、发票属于某一次续费历史，不属于提醒计划。

## 提醒算法

### 保存事项时

保存事项时，系统保存当前到期日和下次提醒开始日。

如果请求中没有传入下次提醒开始日，则使用当前到期日减去提前提醒天数生成默认值。

保存时不判断当前到期日是否早于今天，也不自动顺延。

### 推送提醒时

推送逻辑以 `next_reminder_start_date` 为优先依据。

每日提醒：

```text
今天 >= next_reminder_start_date
且 今天 <= current_expiry_date
```

只提醒一次：

```text
今天 == next_reminder_start_date
```

逾期事项：

```text
今天 > current_expiry_date
且事项状态为 active
```

逾期事项继续推送逾期提醒，直到用户确认续费或停用。

推送仍保留每日去重机制，避免同一事项同一天重复推送。

### 确认续费时

用户点击确认续费后，系统执行以下逻辑：

```text
previous_expiry_date = current_expiry_date
new_expiry_date = current_expiry_date + renewal_period
next_reminder_start_date = new_expiry_date - remind_days_before
```

然后：

1. 创建一条续费历史。
2. 将事项的当前到期日更新为续费后到期日。
3. 将事项的下次提醒开始日更新为新的提醒开始日。
4. 将事项状态设置为 active。

如果用户在到期日前确认续费，例如：

```text
当前到期日：2026-08-13
下次提醒开始日：2026-08-05
确认续费日期：2026-08-07
周期：1 年
提前提醒：8 天
```

系统记录：

```text
续费前到期日：2026-08-13
续费后到期日：2027-08-13
新的下次提醒开始日：2027-08-05
```

如果用户在到期日当天或逾期后确认续费，也使用相同规则。

## 附件管理

附件只绑定到续费历史。

规则：

- 同一次续费历史可以有多份合同。
- 同一次续费历史可以有多份发票。
- 上传是新增附件，不是替换附件。
- 合同和发票都可选。
- 发票可以后补。
- 附件可以查看、下载、删除。

前端 UI：

```text
续费历史表格
  每条记录可展开
    展示该次所有附件
    支持上传合同
    支持上传发票
    支持查看
    支持下载
    支持删除
```

## 后端改动

### 数据库

在 `subscription_records` 增加字段：

```sql
next_reminder_start_date DATE NULL COMMENT '下次提醒开始日'
```

历史数据迁移默认值：

```text
next_reminder_start_date = current_expiry_date - remind_days_before
```

### Entity 和 DTO

更新：

- `SubscriptionRecord`
- `CreateSubscriptionDto`
- `UpdateSubscriptionDto`
- `SubscriptionRecord` 前端类型

新增字段：

```text
next_reminder_start_date?: string
```

### Service

更新 `SubscriptionService`：

- 创建事项时保存或默认生成 `next_reminder_start_date`。
- 更新事项时保存或重新默认生成 `next_reminder_start_date`。
- 推送查询改为优先使用 `next_reminder_start_date`。
- 确认续费后自动更新 `current_expiry_date` 和 `next_reminder_start_date`。

新增附件删除能力：

- 校验附件属于当前套账。
- 删除数据库记录。
- 删除磁盘文件，若磁盘文件不存在，不影响数据库记录删除。

### Controller

更新订阅控制器：

- 暴露附件删除接口。
- 保持现有上传、预览、下载接口。

## 前端改动

### 订阅列表编辑表单

表单改为展示：

- 当前到期日
- 下次提醒开始日
- 周期数值
- 周期单位
- 提前提醒天数
- 提醒方式

交互规则：

- 修改当前到期日或提前提醒天数时，若用户没有手工改过下次提醒开始日，则自动刷新默认提醒开始日。
- 用户手工改过下次提醒开始日后，尊重用户输入。
- 预览区域展示当前规则下的近 5 轮提醒计划。

预览展示：

- 次数
- 提醒日期或提醒区间
- 预计到期日

### 订阅详情页

详情页展示：

- 当前到期日
- 下次提醒开始日
- 提醒方式
- 提前提醒天数

续费历史改成展开行附件管理。

### 续费确认

确认续费弹窗保留：

- 续费备注
- 可选合同附件
- 可选发票附件

确认后：

- 创建续费历史。
- 上传所选附件到该续费历史。
- 刷新事项详情和续费历史。

## 错误处理

- 附件上传没有文件时，前端不调用上传接口。
- 删除不存在的附件返回明确错误。
- 删除磁盘文件失败时，返回错误并保留数据库记录。
- 事项不存在、附件不属于当前套账时，返回业务错误。
- 提醒开始日为空时，后端按当前到期日和提前提醒天数自动生成。

## 测试计划

### 后端测试

新增或更新服务测试：

- 创建事项时默认生成下次提醒开始日。
- 创建事项时保留手工填写的下次提醒开始日。
- 允许保存逾期事项，不自动顺延。
- 每日提醒在提醒开始日至到期日之间推送。
- 一次提醒只在提醒开始日推送。
- 逾期事项继续推送。
- 确认续费后顺延当前到期日和下次提醒开始日。
- 附件删除校验套账并删除记录。
