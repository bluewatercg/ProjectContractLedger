# 多套账管理优化说明

## 优化概述

针对用户管理多条线（多套账）的需求，我们进行了以下优化：

### 1. 新增数据时显示套账选择器

**问题：** 之前新增客户、合同等数据时，系统自动使用当前选中的套账，用户无法明确指定数据归属。

**解决方案：**
- 在新增表单中添加"所属套账"选择器
- 默认选中当前套账，但用户可以修改
- 创建后套账归属不可修改（保证数据一致性）
- 只有当用户有多个套账权限时才显示选择器

**影响范围：**
- ✅ 客户管理 - 新增/编辑客户表单
- 🔄 合同管理 - 待实现
- 🔄 发票管理 - 待实现
- 🔄 支付管理 - 待实现

**使用方式：**
1. 进入"新建客户"页面
2. 在表单顶部看到"所属套账"选择器
3. 选择要归属的套账（默认为当前套账）
4. 填写其他信息并保存

### 2. 列表页面添加"查看全部"功能

**问题：** 用户只能查看当前套账的数据，无法跨套账查看全部数据。

**解决方案：**
- 在列表页面工具栏添加"查看全部套账"开关
- 开启后显示所有套账的数据
- 在表格中增加"所属套账"列，显示数据归属
- 关闭后恢复只显示当前套账数据

**影响范围：**
- ✅ 客户管理 - 客户列表
- 🔄 合同管理 - 待实现
- 🔄 发票管理 - 待实现
- 🔄 支付管理 - 待实现

**使用方式：**
1. 进入客户列表页面
2. 在搜索栏右侧看到"查看全部套账"开关
3. 打开开关，查看所有套账的客户
4. 表格中会显示"所属套账"列
5. 关闭开关，恢复只显示当前套账

### 3. 新增通用 KitSelect 组件

**功能：**
- 可复用的套账选择器组件
- 自动加载用户有权限的套账列表
- 支持自动选中当前套账
- 显示当前套账标签
- 支持禁用、清空等配置

**组件位置：**
`/apps/frontend/src/components/KitSelect.vue`

**使用示例：**
```vue
<template>
  <KitSelect
    v-model="form.kitId"
    :disabled="isEdit"
    placeholder="请选择套账"
    :auto-select-current="true"
  />
</template>

<script setup>
import KitSelect from '@/components/KitSelect.vue'
import { ref } from 'vue'

const form = ref({
  kitId: null
})
</script>
```

**Props 说明：**
- `modelValue`: 绑定的套账 ID
- `placeholder`: 占位符文本（默认："请选择套账"）
- `width`: 选择器宽度（默认："200px"）
- `disabled`: 是否禁用（默认：false）
- `clearable`: 是否可清空（默认：false）
- `autoSelectCurrent`: 是否自动选择当前套账（默认：true）

## 技术实现

### 前端改动

1. **新增组件**
   - `KitSelect.vue` - 套账选择器组件

2. **修改文件**
   - `CustomerForm.vue` - 添加套账选择器
   - `CustomerList.vue` - 添加查看全部开关和套账列
   - `customer.ts` (API) - 添加 viewAll 参数
   - `types.ts` - Customer 接口添加 kit_id 字段

### 后端改动

1. **修改文件**
   - `customer.controller.ts` - 支持 viewAll 查询参数
   - 当 `viewAll=true` 时，不传 kitId，返回所有套账数据

### API 变更

**获取客户列表 API**
```
GET /api/v1/customers?viewAll=true
```

**参数说明：**
- `viewAll`: 可选，布尔值
  - `true`: 查看所有套账的数据
  - `false` 或不传: 只查看当前套账的数据

## 数据流程

### 新增数据流程

```
1. 用户打开新增表单
   ↓
2. KitSelect 组件自动选中当前套账
   ↓
3. 用户可以修改套账选择
   ↓
4. 提交表单时，kitId 随数据一起发送
   ↓
5. 后端使用表单中的 kitId（而非 header 中的）
   ↓
6. 数据保存到指定套账
```

### 查看全部流程

```
1. 用户打开列表页面（默认显示当前套账）
   ↓
2. 用户打开"查看全部套账"开关
   ↓
3. 前端发送 viewAll=true 参数
   ↓
4. 后端不过滤 kit_id，返回所有数据
   ↓
5. 前端显示所有套账数据，并显示"所属套账"列
   ↓
6. 用户关闭开关，恢复只显示当前套账
```

## 使用场景

### 场景 1: 为不同条线创建客户

**需求：** 用户负责 A、B 两条线，需要为 B 线创建客户

**操作步骤：**
1. 点击"新建客户"
2. 在"所属套账"中选择"B 线"
3. 填写客户信息
4. 保存

**结果：** 客户归属到 B 线，只有在切换到 B 线或开启"查看全部"时才能看到

### 场景 2: 查看所有条线的客户

**需求：** 用户想查看所有条线的客户总览

**操作步骤：**
1. 进入客户列表
2. 打开"查看全部套账"开关
3. 查看所有客户，表格显示每个客户的所属套账

**结果：** 可以看到所有套账的客户，并能区分归属

### 场景 3: 分条线查看数据

**需求：** 用户想单独查看某条线的数据

**操作步骤：**
1. 在顶部套账选择器中切换到目标套账
2. 页面刷新，显示该套账的数据
3. 或者关闭"查看全部套账"开关

**结果：** 只显示当前套账的数据

## 注意事项

### 1. 数据归属不可修改

- 创建时选择的套账归属后续不可修改
- 编辑表单中套账选择器为禁用状态
- 这样设计是为了保证数据一致性和账目清晰

### 2. 权限控制

- 用户只能看到自己有权限的套账
- 套账选择器只显示用户被授权的套账
- 后端会验证用户对套账的访问权限

### 3. 单套账用户

- 如果用户只有一个套账权限，不显示套账选择器
- 自动使用唯一的套账，简化操作

### 4. 查看全部功能

- "查看全部"功能适合管理员或负责多条线的用户
- 可以快速对比不同套账的数据
- 不影响数据的实际归属

## 常见问题

### Q1: 为什么创建后不能修改套账？

**A:** 为了保证账目清晰和数据一致性。如果允许随意修改套账归属，可能导致：
- 账目混乱
- 统计数据不准确
- 审计追溯困难

如果确实需要修改，建议：
1. 在原套账中删除数据
2. 在新套账中重新创建

### Q2: 查看全部时能否编辑其他套账的数据？

**A:** 可以。查看全部只是改变了数据的显示范围，不影响编辑权限。只要用户有该套账的权限，就可以编辑。

### Q3: 如何给用户授权多个套账？

**A:** 在"套账管理"页面：
1. 选择要授权的套账
2. 点击"用户授权"
3. 选择用户并设置是否为默认套账
4. 保存

### Q4: 单套账用户能看到套账选择器吗？

**A:** 不能。为了简化操作，单套账用户不显示套账选择器，自动使用唯一的套账。
